1 The common case: resolved before anyone looks

A transient gateway timeout. The failure is isolated, the data is sound, and one retry is the correct answer. This is the majority of real alerts, and it is the case that wastes the most human time today.

live run · gpt-5.6-luna what the agent did at 06:05
  • 1 It checks whether this is already known before doing anything else. If Sam is already working this problem, a second alert must not trigger a second fix. That check runs before any remediation is contemplated.
  • 2 It asks whether the data is the problem. Refreshing a report never fixes bad data, so that question is settled first — by a second agent that reads the actual rows, not by a guess.
  • 3 "Isolated, therefore safe to retry" is a conclusion from evidence. Two prior refreshes completed; one failed. That is read from Power BI, not inferred from the wording of the alert.
  • 4 One retry. Verified. Not "triggered and hoped" — the agent confirms the refresh actually completed before it reports success.

Priya's morning: unchanged. That is the entire outcome, and it is the point.

Sam's morning: one notification, already resolved, with the evidence attached.

2 When it needs a human, it asks — with the evidence

Some failures cannot be fixed by retrying, and some fixes are too consequential to make unattended. The agent is not allowed to decide which of those it is.

deployed container · East US a failure that retrying cannot fix
  • 1 It declined to retry, and said why. The data source credentials need updating; refreshing again cannot repair that. Retrying would have burned the single permitted remediation on an action that could not work.
  • 2 Knowing when not to act is the harder half. An agent that always does something is easy to build and impossible to trust.
  • 3 Sam gets a decision to make, not a mystery to investigate. Report, error, what was checked, what was ruled out, and what needs a person.
rendered from the live payload what lands in Sam's channel
  • 1 Everything needed to agree or disagree, in one card. Sam does not have to open a console to form a view.
  • 2 Secrets are stripped before this leaves the process. A connection string in an error message never reaches a channel with a wider audience than the system it came from.

Being straight about this one. The card above is generated from the payload the agent really produces, but delivery to a channel is not wired in this build — Microsoft retired the old Teams webhook connectors on 22 May 2026 and the replacement has to be created by hand. It is a two-minute step, documented in the run sheet. Nothing else on this page is pending.

3 When Sam says no, that is the end of it

Some actions require a human to agree first. The interesting half of an approval is what happens when the answer is no — that is where an agent either respects the boundary or works around it.

live run a proposed fix, declined
  • 1 The action was never dispatched. Not attempted and rolled back — never sent. There is no path from a declined proposal to a change in your tenant.
  • 2 It did not try something else instead. A denial is not a puzzle to route around.
  • 3 The decision is recorded with the incident. Who was asked, what they said, and when — so "why was nothing done?" has an answer six weeks later.

4 "Whose agent is this?"

The question every security review asks, and the one most agent demos cannot answer. It is worth knowing what the agent is before deciding what it may do.

live directory read triage-demo identity --check-scope
  • 1 Each agent is its own identity in your directory, not a shared service account. What it did is attributable to it.
  • 2 A named person is accountable. Entra records a sponsor. When something goes wrong at 3am the directory can answer "who owns this?".
  • 3 There is no password to leak. No key, no secret, nothing to rotate — it authenticates with a federated credential. That is a different property from "the secret is stored carefully".
  • 4 The agents that think hold nothing at all. Only the one that acts has permissions, and it can read exactly one mailbox — a boundary the system tests on itself at startup and refuses to run without.

5 What actually changed

TodayWith this running
Priya Opens a stale report and cannot tell. Or spots it, and loses a morning chasing whether the number is real. Opens a current report. Learns nothing about any of it.
Sam An alert mailbox nobody reads. Reconstructs 06:02 from logs, hours later. One notification per genuine incident, with the evidence and the reasoning attached, and a decision to make only when a decision is actually needed.
Whoever asks later "I think it was the gateway?" Every terminal outcome recorded — including the refusals, the crashes and the declined approvals.

The claim being made is narrow, deliberately. This does not fix your data platform. It removes the gap between something breaking and somebody competent looking at it, and it makes the routine cases stop consuming attention — while refusing, loudly and in writing, to make the consequential ones on its own.
